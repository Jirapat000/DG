# ทดสอบ ESP32-CAM หนึ่งภาพ

สเก็ตช์นี้เป็นโหมดต้นแบบสำหรับทดสอบ `กล้อง → Wi-Fi → HTTPS → API → วิเคราะห์ภาพ` แบบสั่งทีละครั้ง โดยไม่มีเซนเซอร์ ไม่มี deep sleep และไม่ใช้ SD card เพื่อลดภาระตอนเริ่มระบบ ตั้งภาพเป็น VGA, ใช้ framebuffer เดียว และลดกำลังส่ง Wi-Fi เป็น 8.5 dBm สำหรับทดสอบใกล้เราเตอร์ แฟลชเริ่มต้นปิด บอร์ดรายงาน heartbeat ทุก 15 วินาทีและตรวจคำสั่งจากหน้าเว็บ `/test` ทุก 5 วินาที

## เตรียมไฟล์

1. คัดลอกโฟลเดอร์ `test_one_shot` ไปยังเครื่องที่ใช้ Arduino IDE
2. คัดลอก `secrets.h` ที่ตั้งค่าจริงของบอร์ดมาไว้ข้าง `.ino` แล้วตรวจว่า SSID, รหัส Wi-Fi, `DEVICE_ID`, `DEVICE_TOKEN` และ `API_HOST` ตรงกับค่าที่ใช้บน Render (อย่าเผยแพร่หรือ commit ไฟล์นี้)
3. เปิด `test_one_shot.ino` ใน Arduino IDE เลือก `AI Thinker ESP32-CAM`, พอร์ต COM และความเร็ว Serial `115200`
4. อัปโหลดตามวิธีปกติของบอร์ด (GPIO0 ลง GND ตอนอัปโหลด; ถอดออกและกด RESET หลังอัปโหลด)

## วิธีทดสอบ

1. เปิด Serial Monitor ที่ `115200 baud` และเลือก line ending `Newline`
2. ตรวจ `RESET REASON`, `CAMERA: ready` และ `Wi-Fi connected`; พิมพ์ `i` เพื่อดู RSSI, IP, heap และ PSRAM
3. เปิดหน้าเว็บ `/test`; สถานะต้องขึ้น **เชื่อมต่อแล้ว** ก่อน ปุ่ม **เปิดแฟลช/ปิดแฟลช** ส่งคำสั่งไปยังบอร์ด และปุ่ม **สั่ง ESP32-CAM ถ่ายและวิเคราะห์** จะขอภาพหนึ่งภาพ
4. ทางเลือก: พิมพ์ `c` ใน Serial Monitor เพื่อถ่ายและอัปโหลดภาพหนึ่งภาพ หรือพิมพ์ `i` เพื่อดูสถานะ
5. เก็บผล `API STATUS`, `HEADER` และ `API BODY` ทั้งหมด หากล้มเหลว ส่งข้อความเหล่านี้มาให้ตรวจได้ โดยปิดบัง IP ภายในถ้าต้องการ

## ใช้กับแบตเตอรี่

ขณะทดสอบนี้บอร์ดต้องเปิด Wi-Fi และกล้องค้างไว้เพื่อรับคำสั่งจากเว็บ จึงไม่เข้า deep sleep และอาจใช้แบตเตอรี่เร็ว โดยเฉพาะเมื่อเปิดแฟลช ควรใช้แหล่งจ่ายที่รองรับกระแสพีกของ ESP32-CAM และปิดแฟลชจากหน้าเว็บเมื่อไม่ใช้

## อ่านผล

- `Camera init failed` / `CAMERA: failed`: ตรวจรุ่นบอร์ด, สายแพกล้อง และไฟเลี้ยง
- `Wi-Fi failed`: ตรวจ Wi-Fi 2.4 GHz และค่าที่อยู่ใน `secrets.h`
- `TLS/DNS/connect failed`: ยังต่อ HTTPS กับ API ไม่ได้ ก่อนจะมี HTTP status
- `UPLOAD` ส่งไม่ครบ: ตรวจสัญญาณ Wi-Fi, แหล่งจ่ายไฟ และขนาดภาพ
- `HTTP/1.1 502`: คำขอไปถึง reverse proxy แต่ backend ปลายทางไม่ตอบสำเร็จ; เก็บเวลา UTC และดู Render logs
- `413`: ภาพใหญ่เกินขีดจำกัดที่ proxy/API รับ
- `401`/`403`: ตรวจ `DEVICE_ID` และ `DEVICE_TOKEN` ให้ตรงกับ Render
- `200`/`201`: อ่าน JSON ใน `API BODY` ดู `model_status`, `coverage`, `detections`, `alert_sent` และ `alert_status`

คำสั่ง `c` และคำสั่งจากหน้าเว็บส่งภาพไปยัง endpoint จริง `/api/captures` หนึ่งครั้ง และสร้าง capture record เมื่อ API ทำงาน คำสั่งจากเว็บจะถูกบันทึกสถานะจนแสดงผลบนหน้าเว็บ ภาพจริงที่เข้าเกณฑ์พื้นที่ขยะอาจทำให้ backend ส่ง LINE OA broadcast ได้
